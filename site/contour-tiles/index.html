Contour Map Tiles

Free contour-line vector tiles for the whole world — 10 m intervals derived from the Copernicus GLO-30 elevation model, smoothed so they look like a printed topo map rather than a pixel lattice. One PMTiles file per archive, no API key, no server required.

World — every land mass except the ice sheets zoom 9–15 10 m interval, 50 m index ~232 M tiles Free, attribution required

Live demo — contours are range-read straight out of the world archive in your browser, no tile server involved; basemap by OpenFreeMap. Zoom in for full 10 m detail, or drag anywhere on Earth. Lines appear from zoom 9.

Both share one schema, one zoom range and one build pipeline, so a style written for either works with the other unchanged. Over Australia the two differ only in the source elevation model: the Australia archive uses Geoscience Australia's DEM-S, which has had drainage lines and vegetation artefacts cleaned up, so it is still the better pick for Australian terrain. Everywhere else, use the world archive.

Quick start (MapLibre GL JS)

The archives are served with CORS enabled and HTTP range support, so MapLibre can read tiles directly from them using the pmtiles protocol — no tile server involved. A client only ever fetches the directory entries and tiles for the area on screen, so the size of the world archive is irrelevant to page weight:

<!-- maplibre-gl v5 is the last major with a script-tag (UMD) build; v6+ is ESM-only -->
<script src="https://cdn.jsdelivr.net/npm/maplibre-gl@5.24.0/dist/maplibre-gl.js"></script>
<script src="https://cdn.jsdelivr.net/npm/pmtiles@4.5.0/dist/pmtiles.js"></script>
<script>
  const protocol = new pmtiles.Protocol();
  maplibregl.addProtocol("pmtiles", protocol.tile);

  const map = new maplibregl.Map({ container: "map", /* your base style */ });
  map.on("load", () => {
    map.addSource("contours", {
      type: "vector",
      url: "pmtiles://ARCHIVE_URL",
      attribution: "Contours produced using Copernicus WorldDEM-30 © DLR e.V. 2010-2014 and © Airbus Defence and Space GmbH 2014-2018 provided under COPERNICUS by the European Union and ESA; all rights reserved",
    });
    // is_index arrives as the STRING "0"/"1", so wrap it in to-number —
    // ["==", ["get","is_index"], 1] silently matches nothing.
    map.addLayer({
      id: "contour-regular", type: "line",
      source: "contours", "source-layer": "contour",
      filter: ["!=", ["to-number", ["get", "is_index"]], 1],
      paint: { "line-color": "rgb(179,134,89)", "line-width": 0.5, "line-opacity": 0.5 },
    });
    map.addLayer({
      id: "contour-index", type: "line",
      source: "contours", "source-layer": "contour",
      filter: ["==", ["to-number", ["get", "is_index"]], 1],
      paint: { "line-color": "rgb(166,116,66)", "line-width": 1.1, "line-opacity": 0.65 },
    });
  });
</script>

Swap the URL for the Australia archive (and its CC-BY attribution, see below) to use that one instead. The same files work anywhere PMTiles is supported: MapLibre (web and native), QGIS 3.32+, Felt, and the pmtiles CLI.

Plain z/x/y endpoint

If your client can't speak PMTiles, a conventional tile endpoint fronts each archive, edge-cached on Cloudflare's network:

https://tiles.contour-map-tiles.net/world/{z}/{x}/{y}.pbf      # world archive
https://tiles.contour-map-tiles.net/contours/{z}/{x}/{y}.pbf   # Australia archive

Empty tiles (ocean, the ice sheets) answer 204 rather than 404; GET /health reports each archive. Prefer the pmtiles:// URL where you can — it's served straight from storage with no request limits in front of it.

Extract a region

The world archive is ~750 GB, so you almost certainly don't want all of it. Pull just your area of interest with the pmtiles CLI — it range-reads only the tiles inside your bounding box, so it's fast and small (Switzerland is a few GB, Tasmania ~350 MB, a single national park usually a few MB):

# bbox = minLon,minLat,maxLon,maxLat  (this one is Switzerland)
pmtiles extract ARCHIVE_URL \
  switzerland-contours.pmtiles \
  --bbox=5.9,45.8,10.5,47.9

Extracts of the world archive from mountain regions run larger than the same area of Australia: there is simply more relief to draw. Cap the zoom with --maxzoom=13 for a much smaller file if 20 m detail is enough.

The Australia archive is small enough to take whole (11.9 GB):

curl -O AUSTRALIA_URL

Need MBTiles for an offline mobile app? pmtiles convert does the conversion.

What's in the tiles

LayerOne vector layer, contour (MVT/pbf, gzip)
Attributeselevation — metres, a number · is_index — "1" on 50 m multiples (bold "index" lines), else "0". Note the quotes: is_index is encoded as a string, so compare it with ["==", ["to-number", ["get", "is_index"]], 1] — a plain ["==", ["get", "is_index"], 1] is type-strict in MapLibre and silently matches nothing, which renders every line at intermediate weight with no labels.
Interval10 m contours, 50 m index contours
Zoom rangez9–z15 (overzooms cleanly beyond 15)
Density by zoomz9: 100 m contours · z10–11: 50 m · z12: 20 m · z13+: full 10 m
CoverageWorld: every land mass covered by the Copernicus DEM, excluding the Antarctic and Greenland ice sheets (contours there are enormous and almost meaningless). Australia: mainland + Tasmania (112.92°E–154°E, 43.86°S–10°S).
Source DEMWorld: Copernicus GLO-30 (~30 m, a surface model — tree canopy and buildings are in it). Australia: Geoscience Australia 1-second SRTM DEM-S (smoothed variant, ~30 m)
SizeWorld: ~750 GB, ~232 million tiles. Australia: 11.9 GB, ~8.5 million tiles
Built withGDAL (cubic-spline oversampled warp + gdal_contour) and tippecanoe

The DEM is warped to 2× its native density with cubic-spline resampling before contouring, which traces smooth curves between the 30 m elevation samples instead of polygonal lines along the pixel lattice. The world is processed as ~7,000 2°×2° cells with buffered edges, so contours join seamlessly across cell boundaries, and the cells are grouped into continental shards that are tiled separately and stitched into the one archive.

How it was built

These tilesets are a by-product of building offline topo maps for a hiking-trail guide app. The full pipeline — chunked, resumable, per-cell and per-shard — is open source in that repo: scripts/build-contours-world.ts for the world and scripts/build-contours-australia.ts for Australia, with the rented-machine runbook in docs/world-contours-remote-build.md. The Australia archive was built on a laptop over a day; the world took ~7,000 cells on an 80-core box, ten continental tippecanoe merges, and a final join on a 3 TB NVMe instance. A write-up of the build (and the failures along the way) is coming soon.
